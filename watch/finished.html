Finished or failed?

Once a job leaves squeue, sacct tells you how it ended. The .err file tells you why.

1 · How did it end?

sacct -X -S 2026-09-01 -o JobID,JobName%15,Partition,State,Elapsed

-S = show jobs since this date. Change it to a recent date.

3 · Ask only for what you need

Every GPU, core and GB you request is blocked for other users while your job runs, even if your job never uses it. When everyone asks only for what they need, more jobs fit on the cluster and everyone gets GPUs sooner, including you.

After a job finishes, seff shows how much it really used:

seff 350113
HPC · real output
Job ID: 350113
State: COMPLETED (exit code 0)
Cores per node: 8
CPU Efficiency: 54.79% of 23-23:12:00 core-walltime
Job Wall-clock time: 2-23:54:00
Memory Utilized: 37.85 GB
Memory Efficiency: 31.54% of 120.00 GB

This job asked for 120 GB but used only 38 GB. For the next run, about 50 GB is enough: a little more than it used, not more than twice.

  • Memory: set --mem a little above Memory Utilized.
  • Cores: if CPU Efficiency is low, lower --cpus-per-task.
  • Time: set --time a little above the real run time. Shorter jobs also start sooner.
  • GPUs: ask for more than one GPU only if your code really uses them all.
